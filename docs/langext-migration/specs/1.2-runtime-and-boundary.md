# Spec 1.2: runtime and boundary

Status: **implemented and committed 2026-11-15 (63647bb).** Approved the same day, with the open questions and UX
suggestions decided by the owner (sections 5 and 10). Section 3.10 lists where the code differs from the approved
text. Tests before and after: unit 392 → 480 (1 skipped, KI-93), integration 1384 → 1399 (38 skipped), no failures.
Build warnings: 120 before and after.

Implements C2 from the plan, with TD-11, Q1 (the boundary half), Q2a, Q2c, Q3, F-9 and the run summary. It also
corrects two spike deviations (plan part 2): the boundary defers (TD-11), and the run summary is ported.

## 1. Scope

**In scope**

- **`Grimoire/Functional/`, productionised from the spike.** The spike's files aren't on this branch, so they are
  rewritten here, not copied. Spike code that depends on 1.3 or 1.4 (Dapper, `DiscordError`, `GrimoireErrors`,
  `DomainBridge`) is left out.
- **Capabilities that the boundaries need** (OQ-2): `ITimeIO`, `ILogIO`, `IAlertIO`, `IGuildLogIO`, `ITraceIO` and
  `ICommandIO`, each with a live implementation. `IDatabaseIO` comes in 1.3, `IDiscordIO` in 1.4 and `ISettingsIO` in
  3.1, and each adds one field to `GrimoireEnv` and one `Has<>` per runtime.
- **Two runtimes**, `GrimoireRuntime` (events and workers) and `CommandRuntime` (adds `ICommandIO`), and the effect
  modules (`Clock<RT>`, `Log<RT>`, `Alerts<RT>`, `GuildLogs<RT>`, `Trace<RT>`, `Command<RT>`, `Effect`).
- **The command boundary:** privacy, then validate, then defer, then act, then render (section 2.1). This includes
  the `[PrivateReply]` attribute (TD-11), the `Reply` value, Q2c's colours, Q3's ephemeral refusals, the text-command
  delivery rules (OQ-1: public replies, a 🔒 reaction for private commands, DMs for the commands that ask for them),
  and the generic "[ID …]" reply plus an alert for `Unavailable` and defects (Q1).
- **The event boundary:** runs a handler's effect, logs and alerts by case, and never throws to DSharpPlus (C2).
- **The worker boundary:** `EffectBackgroundService`, with the tick loop, per-item backoff that never drops a
  failure (F-9), the consecutive-failure escalation, and `GenericBackgroundService`'s five-minute run summary, all held
  in one `Atom`.
- **A fake runtime for unit tests:** the same runtime records, built from recording fakes in `Grimoire.UnitTests`.
- **Test-only probe command, handler and worker** in the integration project, so the boundaries are tested inside
  the real host before any feature uses them (OQ-3).
- **`CommandHandler`** gets the new outcomes in its "finished" log line (2.1, step 8). Its exception handling stays as
  it is for the old commands and for checks and converters (C2).
- **`docs/architecture.md`**, written in this section (plan part 5, step 2).

**Out of scope**

- Porting any command, handler or worker. `/Warn` is the first, in 3.2. Until then, nothing in production runs
  through the new boundaries. Old and new code run side by side (plan rule 2).
- Deleting `TryDeferAsync`, `GenericBackgroundService` or the old reply helpers: Phase 5. They aren't marked
  `[Obsolete]` here, because every command would warn until Phase 3 ports it, which drowns the 1.1 burn-down.
- `IDatabaseIO`, Dapper and `Unavailable` from Postgres: 1.3. `IDiscordIO`, `Forbidden` from Discord and the "bot
  missing permissions" guild issue for it: 1.4. Settings as a capability: 3.1.
- Trace ids, spans and metrics: 1.6. The error id gets a capability (`ITraceIO`) here, so 1.6 only changes its live
  implementation.
- Paged replies with buttons (`ReplyPagesAsync`), modals and autocomplete. They keep calling the primitives (T-1,
  "where the shape doesn't fit"). `Reply` covers follow-up pages (KI-30, KI-113).
- F-8. With C2, `CommandHandler` only answers failures from checks and converters, which happen before the command
  method runs and so before any defer. F-8's "respond after a defer" case can't happen for a ported command. It stays
  possible for old commands until they're ported.

**IDs covered:** C2, TD-11, Q1, Q2a, Q2c, Q3, F-9, F-12 (the new worker logs under its own category). No KIs.

## 2. Flow

### 2.1 Command

```
DSharpPlus: checks, converters ──fail──► CommandErrored ──► CommandHandler (unchanged)
   │
   ▼
shell: [Command] method
   runner.Run(ctx, privacy, input: Invocation → Validation<Error, TIn>, act: TIn → Eff<CommandRuntime, Reply>)
   │  copies ctx into an Invocation record (C5), builds a LiveCommandIO, runs the effect below
   ▼
CommandBoundary<RT>.Run                                                 Eff<RT, CommandOutcome>, never fails
 1. privacy     static [PrivateReply], or the command's Invocation → Eff<RT, Privacy>           effect (cached read)
 2. delivery    Delivery.For(privacy, kind)                                                     pure decision
      text + Private ──► Command.React(🔒), nothing else runs (OQ-1, UX-3)
 3. validate    input(invocation)                                                               pure
      Fail ──► refuse at once: slash ephemeral initial response, text public reply or DM ──► outcome = case
 4. defer       Command.Defer(delivery)                                                         effect
 5. act         act(valid)  →  Fin<Reply>                                                       effect
 6. render      Succ  ──► Command.Reply(delivery, embed, follow-ups) ──► GuildLogs.Send(log)    effect
                Fail(Invalid | NotFound | Forbidden) ──► Command.Refuse(colour, messages)       effect
                Fail(Unavailable | defect) ──► Log.Error + Alerts.Send ──► Command.Refuse(generic "[ID …]")
                cancelled by shutdown ──► Log.Information, no reply
 7. a failure in steps 4–6's own I/O (the defer, the reply) ──► Log.Warning + Alerts.Send, no retry (Q25)
 8. the runner stores the CommandOutcome for CommandHandler's CommandExecuted log line
```

- **Pure:** the privacy decision for a static command, `Delivery.For`, `input`, `Outcome.Classify`,
  `Replies.Refusal`, `Replies.Generic`, and `Colour.Of`.
- **Effects:** a data-dependent privacy read, the defer, `act`, the reply, the guild log post, logs and alerts.
- **Order of reporting:** the log line and the alert go before the reply, as `CommandHandler` does today, because
  the reply is the step most likely to fail (the interaction expired or was deleted).
- **A throw while building** the input or the effect (in the shell, before anything runs) is caught by the runner
  and handled as a defect. The runner takes delegates for this reason.

### 2.2 Event

```
DSharpPlus ──► IEventHandler<TArgs>.HandleEventAsync(client, args)
   │  shell: runner.RunEvent(nameof(Handler), guildId, () => Pipeline<GrimoireRuntime>.Run(Record.From(args)))
   ▼
EventBoundary<RT>.Run                                                         Eff<RT, Unit>, never fails
   Succ                                ──► nothing
   Fail(NotFound)                      ──► Log.Debug        (the thing was gone: a race with a delete)
   Fail(Invalid | Forbidden)           ──► Log.Warning + Alerts.Send(Warning)
   Fail(Unavailable)                   ──► Log.Error   + Alerts.Send(Urgent)
   Fail(defect)                        ──► Log.Error   + Alerts.Send(Urgent)
   cancelled by shutdown               ──► Log.Information
```

The runner catches nothing else, because the boundary effect can't fail. So `IClientErrorHandler` is never called for
a ported handler. It stays registered for the old handlers (C2).

### 2.3 Worker

```
EffectBackgroundService.ExecuteAsync          shell: random start delay, then the schedule
   repeat(Schedule.spaced(interval), Supervised(Tick))
Supervised(tick)                                                        Eff<GrimoireRuntime, Unit>, never fails
   start = Clock.Timestamp
   tick  ──► Item(key, work) for each item ──┐
   │   Item: backoff says wait ──► skip       │  state: Atom<WorkerState>
   │         work Succ ──► clear backoff      │
   │         work Fail(Invalid|NotFound|Forbidden|defect) ──► record backoff, Log.Warning,
   │                   alert Warning (not for Forbidden), continue with the next item
   │         work Fail(Unavailable) ──► leave backoff alone, fail the tick (Q38)
   ▼
   Succ ──► consecutive = 0
   Fail ──► consecutive + 1, Log.Error, alert (Urgent from 3 in a row unless NotFound)
   cancelled by shutdown ──► stop
   then: WorkerState.Record(elapsed, failed, now) ──► Some(summary) every 5 min ──► Log.Information
```

- **Pure:** `WorkerState` and all its transitions (`Record`, `Backoff.ShouldAttempt`, `Backoff.Failed`,
  `Backoff.Succeeded`, `Escalation.SeverityFor`).
- **Effects:** the tick's work, the clock, logs and alerts, and the `Atom` swaps.

## 3. Types

All in `Grimoire/Functional/`, namespace `Grimoire.Functional.*`. The boundary core is generic over the runtime, so
unit tests run it with fakes. Only `CommandRunner`, `EventRunner`, `EffectBackgroundService.ExecuteAsync` and the live
capabilities touch DSharpPlus or DI.

### 3.1 Capabilities

Every method returns `IO<A>`, a description of the effect.

```csharp
public interface ITimeIO
{
    IO<DateTimeOffset> UtcNow { get; }
    /// <summary>A monotonic timestamp, as <c>TimeProvider.GetTimestamp</c>. Durations use this, not <c>UtcNow</c>.</summary>
    IO<long> Timestamp { get; }
    IO<TimeSpan> ElapsedSince(long timestamp);
}

/// <summary>A structured log line. <c>Template</c> is a message template, so Serilog keeps the properties.</summary>
public sealed record LogEntry(LogLevel Level, string Category, string Template, Seq<object?> Args,
    Option<Exception> Exception);

public interface ILogIO { IO<Unit> Write(LogEntry entry); }

/// <summary>Wraps <c>IAlertSender</c>, resolved lazily (it depends on <c>DiscordClient</c>, as today).</summary>
public interface IAlertIO { IO<Unit> Send(Alert alert); }

public interface IGuildLogIO { IO<Unit> Send(GuildLogMessageBase message); }

/// <summary>
///     The id a user quotes from the generic error reply. 1.2: 10 random hex characters, as today. 1.6: the trace id.
/// </summary>
public interface ITraceIO { IO<string> ErrorId { get; } }

/// <summary>
///     The reply side of one command invocation. Only <c>CommandRuntime</c> has one, so an event handler or a
///     worker that tries to reply doesn't compile.
/// </summary>
public interface ICommandIO
{
    /// <summary>
    ///     Slash: defer, ephemeral for <c>Ephemeral</c>. Text, <c>Public</c>: start the response. Text,
    ///     <c>DirectMessage</c>: open the invoker's DM channel; fails with <c>Forbidden</c> when their DMs are closed.
    /// </summary>
    IO<Unit> Defer(Delivery delivery);

    /// <summary>Edits the deferred response (or posts in the DM), then sends each follow-up the same way.</summary>
    IO<Unit> Reply(Delivery delivery, DiscordEmbed embed, Seq<DiscordEmbed> followUps);

    /// <summary>
    ///     A refusal or the generic error. Slash, not yet acknowledged: an ephemeral initial response. Slash, deferred:
    ///     deletes the deferred response and follows up ephemerally (KI-21). Text: a public reply, or a DM for
    ///     <c>DirectMessage</c>.
    /// </summary>
    IO<Unit> Refuse(Delivery delivery, DiscordEmbed embed);

    /// <summary>Text only: reacts to the invoking message. Used for 🔒 (private command run as text).</summary>
    IO<Unit> React(string emoji);
}
```

`LiveCommandIO` moves the bodies of `SendPrivateResponseAsync`, `ReplyAsync` and `ReplyWithFollowUpsAsync` into the
capability. The initial response and the defer aren't retried (Q25). Edits and deletes keep `DiscordRetryPolicy`.
The DM uses `ctx.Member.SendMessageAsync`, the same call `GuildLog.DirectMessageAsync` makes today.

### 3.3 The invocation and privacy

```csharp
public enum InvocationKind { Slash, Text }

/// <summary>Who may see a command's replies. Slash: both private cases are ephemeral. Text: see Delivery.For.</summary>
public abstract record Privacy
{
    private Privacy() { }
    public sealed record Public : Privacy;
    /// <summary>Text: 🔒 on the message, and the command doesn't run. For the command-channel commands.</summary>
    public sealed record Private : Privacy;
    /// <summary>Text: the command runs and every reply, refusals included, goes to the invoker's DMs.</summary>
    public sealed record PrivateByDirectMessage : Privacy;
}

/// <summary>How the replies go out. Decided once per run, before validation.</summary>
public enum Delivery { Public, Ephemeral, DirectMessage }

public static class DeliveryRules
{
    /// <summary>None means "react 🔒 and stop".</summary>
    public static Option<Delivery> For(Privacy privacy, InvocationKind kind) => (privacy, kind) switch
    {
        (Privacy.Public, _) => Delivery.Public,
        (_, InvocationKind.Slash) => Delivery.Ephemeral,
        (Privacy.Private, InvocationKind.Text) => None,
        (Privacy.PrivateByDirectMessage, InvocationKind.Text) => Delivery.DirectMessage,
        // C# 14 can't prove the switch complete. Phase 4's closed Privacy and an exhaustive enum check remove this.
        _ => throw new UnreachableException()
    };
}

/// <summary>What a command's core may know about who ran it, where and how. Copied from the context (C5).</summary>
public sealed record Invocation(
    string Command,                     // ctx.Command.FullName
    InvocationKind Kind,
    Option<GuildId> Guild,
    ChannelId Channel,
    UserId User,
    DiscordPermissions Permissions,     // the member's guild permissions; None outside a guild is DiscordPermissions.None
    DateTimeOffset CreatedAt);          // interaction or message timestamp, for the duration log

/// <summary>
///     The command's replies are private (TD-11): <c>Privacy.Private</c>, or <c>PrivateByDirectMessage</c> when
///     <c>DirectMessageOnText</c> is set. Without the attribute, they're public.
/// </summary>
[AttributeUsage(AttributeTargets.Method)]
public sealed class PrivateReplyAttribute : Attribute
{
    public bool DirectMessageOnText { get; init; }
}
```

A command whose privacy depends on data passes `Func<Invocation, Eff<RT, Privacy>>` instead, which reads what it
needs and calls a pure decision. It may not also carry `[PrivateReply]`. A unit test checks every `[Command]` method
for that, by reflection. The three such commands, as their Phase 3 sections will port them (OQ-1):

| Command | Private when | Privacy | Text, private |
|---|---|---|---|
| `/Level` (3.15) | not a moderator and not in the user command channel | `Private` | 🔒 |
| `/Leaderboard` (3.15) | the same | `Private` | 🔒 |
| `/SinLog` (3.6) | not a moderator | `PrivateByDirectMessage` | the log is DMed. This reverses Q36's silent text reply |

### 3.5 Outcome and rendering (pure)

```csharp
/// <summary>What happened, for the reply, the log line and (in 1.6) the span tag.</summary>
public enum CommandOutcome
{
    Success, PrivateOnText, Invalid, NotFound, Forbidden, Unavailable, Defect, Cancelled,
    // set by CommandHandler only, as today:
    CheckFailed, ParseError, BotMissingPermissions
}

public static class Outcome
{
    /// <summary>
    ///     The case of an error. A <c>ManyErrors</c> takes its worst case: Defect, then Unavailable, then Forbidden,
    ///     then Invalid, then NotFound. Any error that isn't one of the four Grimoire cases is a defect (C1), which
    ///     includes language-ext's own <c>Errors.None</c> (an <c>Option</c> bound in an <c>Eff</c> without a case).
    ///     <c>Errors.Cancelled</c> is <c>Cancelled</c> only when the run's own token was cancelled (shutdown); otherwise
    ///     it, and <c>Errors.TimedOut</c>, are <c>Unavailable</c>.
    /// </summary>
    public static CommandOutcome Classify(Error error, bool shuttingDown);
}

public static class Replies
{
    /// <summary>Invalid and Forbidden red, NotFound yellow (Q2c). Mixed: red if any is red.</summary>
    public static DiscordEmbed Refusal(Error error);         // each distinct message, one per line (UX-1)
    public static DiscordEmbed Generic(string command, string errorId);   // UX-2
}
```

`Classify` has no `_ =>` that hides a case: the four Grimoire types are matched, and the fallback is the defect rule
itself. Phase 4 turns this into an exhaustive switch over a `closed` base (plan Phase 4).

### 3.6 Entry points

```csharp
public sealed class CommandRunner(GrimoireEnv env, IHostApplicationLifetime lifetime)
{
    /// <summary>Static privacy from [PrivateReply].</summary>
    public Task Run<TIn>(CommandContext ctx,
        Func<Invocation, Validation<Error, TIn>> input,
        Func<TIn, Eff<CommandRuntime, Reply>> act);

    /// <summary>Privacy that depends on data.</summary>

        Func<Invocation, Eff<CommandRuntime, Privacy>> privacy,
        Func<Invocation, Validation<Error, TIn>> input,
        Func<TIn, Eff<CommandRuntime, Reply>> act);

    /// <summary>Nothing to validate.</summary>
    public Task Run(CommandContext ctx, Func<Invocation, Eff<CommandRuntime, Reply>> act);
}

public sealed class EventRunner(GrimoireEnv env, IHostApplicationLifetime lifetime)
{
    public Task Run(string handler, Option<GuildId> guild, Func<Eff<GrimoireRuntime, Unit>> effect);
}

public abstract class EffectBackgroundService(GrimoireEnv env, TimeSpan interval) : BackgroundService
{
    protected Items Items { get; }                         // as built: a property, so Tick() takes no parameter
    protected abstract Eff<GrimoireRuntime, Unit> Tick();
    internal Task RunTickAsync(CancellationToken token);   // the integration harness drives ticks through this
}

/// <summary>Per-item processing for one worker. Holds the worker's Atom.</summary>
public sealed class Items
{
    /// <summary><paramref name="key" /> must be the same on every tick, as today.</summary>

```

Each run gets its own `EnvIO`, whose token is the application's stopping token. There's no command timeout in 1.2.

### 3.7 Worker state (pure, in one `Atom`)

```csharp
public sealed record WorkerState(int ConsecutiveFailures, RunStats Stats, HashMap<string, ItemBackoff> Backoff);
public sealed record RunStats(long Runs, long Failures, TimeSpan Total, TimeSpan Max, DateTimeOffset NextSummary);
public sealed record ItemBackoff(int Failures, DateTimeOffset NextAttempt);
public sealed record RunSummary(long Runs, long Failures, TimeSpan Average, TimeSpan Max);
```

The rules are `RetryBackoff`'s and `GenericBackgroundService`'s, unchanged: 30 s doubling to 15 min, pruning past
1,000 entries, urgent after 3 consecutive tick failures unless the case is `NotFound`, a summary every 5 minutes.
The summary's working set, heap and gen-2 numbers are read in the logging effect, not stored.

### 3.8 Effect helpers

`Effect.Done`, `Effect.ForSome` and `Effect.Validated` from the spike, plus `Effect.Require(Option<A>, Error)` to turn
an absent value into a case, so no `Option` reaches a `from` clause and becomes `Errors.None`.

### 3.9 The fake runtime (unit tests)

`Grimoire.UnitTests/Functional/Fakes/`: `FakeClock` (settable, advanceable), `FakeLog`, `FakeAlerts`,
`FakeGuildLog` (each records what it got in an `Atom<Seq<_>>`), `FakeTrace` (a fixed id), and `FakeCommandIO`

builds a `GrimoireEnv` from them, and tests use the production `GrimoireRuntime` and `CommandRuntime` records. A
failing capability fails with a chosen `Error`, so outages and defects are one line each.

### 3.10 As built (2026-11-15)

Where the code differs from the approved text above, and why:

- **Refusals on slash are always ephemeral**, made explicit in the boundary (`RefusalDelivery`): a public slash
  command's validation failure is refused with `Delivery.Ephemeral`, not its own `Public` delivery (Q3).
- **Closed DMs are found at the send**, not the defer: Discord accepts opening a DM channel and refuses the message
  (50007). Both points fall back to the 🔒 reaction (section 4).
- **`Errors.None` iterates as no errors at all**, so `Outcome.Classify` treats an empty error as a defect. A unit
  test pins it.
- **`EffectBackgroundService` takes no `ILogger`.** Its logs go through `ILogIO` under the subclass's full type name,
  which is F-12's "own category". `Items` is a protected property.
- **`EventBoundary.Run` returns the `CommandOutcome`** (the shared enum), so tests can assert it; `EventRunner`
  discards it.
- **`LiveCommandIO` maps DSharpPlus exceptions** minimally until 1.4: `UnauthorizedException` → `Forbidden`,
  `NotFoundException` → `NotFound`, server errors, rate limits and `HttpRequestException` → `Unavailable`.
- **Alert types:** `Unavailable` and `UnhandledException` (Urgent), `CommandReplyFailure` (a failed defer, reply or
  log post; Warning), `EventHandlerFailure` (Warning), and the existing `BackgroundTaskFailure` and
  `BackgroundTaskItemFailure`.
- **`CommandHandler`'s `CommandOutcome` enum moved** to `Grimoire.Functional.Boundary`, with the new cases.
- **Test harness:** the fake REST gained the bot's own reaction route (`PUT …/reactions/{emoji}/@me`), and
  `GrimoireTestBot.RunEffectTickAsync<T>()` drives an `EffectBackgroundService`.

## 4. Edge cases

**Commands** (colours per Q2c; "ephemeral" means the slash reply)

| Case | What happens | Outcome | Colour |
|---|---|---|---|
| Checks or a converter fail | DSharpPlus raises `CommandErrored` before our method runs; `CommandHandler` replies as today | CheckFailed / ParseError | yellow (today) |
| `[PrivateReply]`, text command | 🔒 reaction on the message; no validation, nothing runs. Logged at Debug | PrivateOnText | — |
| Data-dependent privacy says `Private`, text command | As above, after the privacy read (`/Level`, `/Leaderboard`) | PrivateOnText | — |
| `PrivateByDirectMessage`, text command | Runs; the reply, any refusal and the generic error go to the invoker's DMs. Nothing is posted in the channel | its case | as below |
| `PrivateByDirectMessage`, text, the member's DMs are closed | Discord refuses a DM only when it's sent, so the act runs and the reply (or refusal) fails with `Forbidden`; 🔒 reaction instead, logged at Debug, no alert. A refused DM channel at the defer does the same, before the act | Forbidden | — |
| The 🔒 reaction fails (message deleted, no Add Reactions permission) | Logged at Debug, no alert | PrivateOnText | — |
| Privacy read fails | Handled like an act failure, but before any defer, so the generic reply is an initial ephemeral response | its case | — |
| One input check fails | Ephemeral initial response with the message; nothing is deferred, so no "thinking…" flash (T-1) | Invalid | red |
| Several input checks fail | One response, each distinct message on its own line (UX-1) | Invalid | red |
| Act fails with `Invalid` / `Forbidden` | Deferred response deleted, ephemeral follow-up (KI-21) | Invalid / Forbidden | red |
| Act fails with `NotFound` | As above | NotFound | yellow |
| A `ManyErrors` mixing `NotFound` and `Invalid` | All messages, red | Invalid | red |
| A `ManyErrors` holding an `Unavailable` | Generic reply: no message from it is shown | Unavailable | UX-2 |
| Act fails with `Unavailable` | Log Error with the id and inner exception, alert, generic "[ID …]" reply | Unavailable | UX-2 |
| Act throws, or fails with an `Exceptional` | Same as `Unavailable`, alert type `UnhandledException` (kept, so `AlertOccurrence` history lines up) | Defect | UX-2 |
| An `Option` bound without `Effect.Require` | `Errors.None` reaches the boundary: a defect | Defect | UX-2 |
| `Errors.TimedOut`, or `Cancelled` while not shutting down | Treated as `Unavailable` | Unavailable | UX-2 |
| Shutdown cancels the run | Log Information, no reply, no alert | Cancelled | — |
| The shell throws while building the input or effect (e.g. `RequiredGuild` without `[RequireGuild]`) | Caught by the runner; a defect | Defect | UX-2 |
| The defer fails (expired, Discord down) | Log Warning and alert; no reply is possible; act doesn't run | the defer's case | — |
| The reply fails after the act succeeded | Log Warning and alert. The act's work stays done; nothing is retried (Q25) | Success, logged with the reply failure | — |
| The guild log post fails after the reply | Log Warning and alert. The reply stands | Success | — |
| The generic reply itself fails | Logged at Warning only; the alert for the original failure already went | as classified | — |
| Act succeeds with follow-up pages | First page edits the deferred response, later pages are follow-ups with the same visibility | Success | the reply's |
| A public text command's refusal or generic error | A public reply, as today (OQ-1) | its case | as above |

**Events**

| Case | What happens |
|---|---|
| `NotFound` | Debug log. No alert: the object was deleted while the handler ran |
| `Invalid`, `Forbidden` | Warning log, Warning alert (daily report), discriminator = handler name |
| `Unavailable`, defect | Error log, Urgent alert, posted at once as an unhandled exception is today (OQ-5). The existing alert cooldown still collapses repeats of the same key |
| The shell throws while copying the args | Caught by the runner; a defect |
| Shutdown | Information log |

**Workers**

| Case | What happens |
|---|---|
| An item fails with `Invalid`, `NotFound` or a defect | Backoff recorded, Warning log, Warning alert `BackgroundTaskItemFailure`, the next item runs |
| An item fails with `Forbidden` | Backoff recorded, Warning log, no alert (today's `UnauthorizedException` rule; 1.4 reports the guild issue at the Discord edge) |
| An item fails with `Unavailable` | Backoff not touched, so the outage doesn't push the item back. The tick fails and the tick alert is raised (Q38) |
| An item in backoff | Skipped this tick |
| A tick fails | Consecutive count + 1, Error log, Warning alert; Urgent from the third in a row unless `NotFound` |
| A tick succeeds after failures | Count back to 0 |
| A tick is cancelled by shutdown | The loop stops; no alert |
| A `TaskCanceledException` from an HTTP timeout | `Unavailable`, an ordinary failure (as today) |
| More than 1,000 backoff entries | Entries idle past 15 minutes are pruned, as today |

## 7. Telemetry

None in 1.2: OpenTelemetry comes in 1.6. 1.2 prepares for it in three places, so 1.6 adds spans without changing a
